# 溯数 TraceNum

面向投研实习生和初级研究员的年报查数工具。用自然语言提问，溯数会检索年报原文、核对口径，答案里的每个数字都能点开，直接翻到年报 PDF 的原页，并用荧光笔标出那个数。查到的数可以一键加入底稿，导出为带页码和核验状态的 Excel。

溯数的检索策略来自一项冻结、盲评的实验：课程论文《资源预算约束下的金融年报问答：自适应多轮检索与外部反馈修正》。实验在比亚迪、威胜信息 2025 年年报上比较了单轮（S1）、固定两轮（S2）和自适应最多三轮（S3）三种策略，S3 答对 16/20 道正式题，S1 为 9/20。溯数默认使用 S3。

## 功能

| 页面 | 做什么 |
|---|---|
| 查数 | 提问 → 实时显示每一轮的检索、生成、规则核验和停止判断 → 答案中的数字逐个核验：原文逐字出现的打勾，计算得出的单独标出 → 点击数字打开年报原页并高亮 |
| 三策略实验台 | 同一道题同时实时运行 S1、S2、S3，每栏显示逐轮轨迹、39,000 tokens 预算条、停止原因，并与论文那次运行的盲评结果对照。每次实时运行都会保存为运行记录，可以按 1/4/8 倍速原样回放，界面会标明录制时间 |
| 实验设计 | 从语料准备到揭盲的 9 步实验流程、结果，以及每条论文发现如何落到产品设计 |
| 底稿 | 汇总查到的数（自动带出指标名、单位、页码和原文行），导出 Excel（数值可直接参与公式计算）或复制为 Markdown 表格 |

找不到可核验的证据时，溯数不会用相近口径替代，也不会编数：它会说明缺了什么，并列出最可能相关的页面。问题超出年报覆盖的年度时，直接说明边界，不调用模型。

## 架构

```
web/ (React + Vite)                     backend/ (FastAPI)
  查数 / 实验台 / 实验设计 / 底稿   ── SSE ──>  server.py  /api/ask  /api/export  /api/pdf
  pdf.js 渲染原页 + 文字层定位高亮                   │
                                                 pipeline.py
                                                   ├─ 载入冻结的 LangGraph 节点（v2/notebooks/07）
                                                   ├─ 调用冻结入口 src.pilot_comparison.run_arm
                                                   ├─ RunLogger 子类：把节点事件推送为流
                                                   ├─ 重排缓存（内存 + 磁盘，单飞）
                                                   └─ 数字核验：答案中的数 ↔ 证据原文，定位表格行名与单位
```

溯数不修改 `v2/` 下的任何冻结文件。检索（bge-base-zh-v1.5 + bge-reranker-v2-m3）、生成（DeepSeek）、反馈规则、预算和停止规则与论文完全一致。

### 和论文实验的差异（如实说明）

- **重排逐条计算**：论文用默认批大小一次给 20 个候选打分，批内会补齐到最长片段。溯数改为逐条打分，以便显示进度并减少补齐带来的计算浪费。`backend/bench_rerank.py` 在三个查询上验证：分数最大差异 < 1e-6，排序完全相同。
- **重排缓存**：相同的（查询，片段）输入直接复用缓存的分数，结果不变。
- **实时结果有随机性**：DeepSeek 在温度为 0 时也不完全确定，同一道题再跑一次，轮次和答案都可能与论文记录不同。实验台把"本次"和"论文那次"并列展示。

## 运行

需要：`finance-rag` conda 环境（论文实验用的同一个）、项目根目录 `.env` 中的 `DEEPSEEK_API_KEY`、Node 18+。目前后端直接读取实验仓库中的冻结管线（`../v2`）和揭盲评分（`../deepseek_workspace`），所以本目录需要放在实验项目根目录下运行。

```powershell
# 后端（首次启动加载模型约 1 分钟）
conda activate finance-rag
cd tracenum\backend
python -m uvicorn server:app --port 8765

# 前端
cd tracenum\web
npm install
npm run dev        # http://127.0.0.1:5180
```

### 演示前

CPU 上每轮检索重排约 30 秒。演示前运行一次预热，把演示题的检索结果写入磁盘缓存：

```powershell
cd tracenum\backend
python prewarm.py --repeat 2
```

第 1 轮检索之后都会命中缓存（< 1 秒）；后续轮次取决于模型改写出的检索词，多彩排几次可以扩大覆盖。

彩排时的每次实时运行都会存进 `backend/recordings/`。`review_recordings.py` 会把每条记录里三种策略的完整答案和论文 Gold 比对；加上 `--feature`，会把每道题与论文盲评最一致的那条设为实验台的演示默认。现场可以先播放回放，再实时运行一次。
